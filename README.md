# อักษรไหว · ร้านแอนิเมชันข้อความภาษาไทย (MVP)

ลูกค้าสมัครสมาชิก/เข้าสู่ระบบ → เลือกสินค้า → จ่ายเงิน → สินค้าเข้าไปอยู่ใน **คลัง** ของบัญชีทันที
→ เปิดคลัง เลือกโปรแกรมตัดต่อที่ใช้ → โหลดไฟล์ที่ตรงกับโปรแกรมนั้นได้ทุกเมื่อ ไม่ต้องมีคนส่งเอง ไม่มีลิงก์ทางอีเมล

ชื่อร้านตั้งได้ที่ `SHOP_NAME` ใน `.env` · โลโก้อยู่ที่ `public/logo.svg` (ตัว "อ" + แถบ 3 ช่วง = ส่วนเข้า · ภาพนิ่ง · ส่วนออก)

> **สถานะ:** การชำระเงินและอีเมลยังเป็น **โหมดทดสอบ** (ปุ่ม "จำลองจ่ายสำเร็จ" / พิมพ์อีเมลลงหน้าจอ) ดูหัวข้อ [ก่อนขายจริง](#ก่อนขายจริงต้องทำอะไร)

## สิ่งที่ต้องมีในเครื่อง

| โปรแกรม | ใช้ทำอะไร | จำเป็นเมื่อ |
|---|---|---|
| Node.js 20 ขึ้นไป | รันเว็บร้าน | ทุกครั้ง |
| ffmpeg (มี libx264, libvpx-vp9, prores_ks) | สร้างไฟล์วิดีโอ | ตอนเรนเดอร์สินค้าใหม่ |
| Chromium ของ Playwright | วาดข้อความไทย | ตอนเรนเดอร์สินค้าใหม่ |

ติดตั้ง ffmpeg: Mac `brew install ffmpeg` · Windows `winget install ffmpeg` · Ubuntu `sudo apt install ffmpeg`

## ติดตั้งและรัน (คำสั่งเดียว)

```bash
npm install && npm start
```

เปิด http://localhost:3000

- ครั้งแรกระบบจะสร้างไฟล์ `.env` ให้เอง พร้อมสุ่ม secret และ **พิมพ์รหัสผ่านหลังบ้านออกมาบนหน้าจอ** (ดูได้อีกทีใน `.env` บรรทัด `ADMIN_PASSWORD`)
- หลังบ้าน: http://localhost:3000/admin ผู้ใช้ `admin`
- ลองซื้อ: สมัครสมาชิก (อีเมลอะไรก็ได้) → เลือกสินค้า → "ซื้อเลย" → กด "จำลองจ่ายสำเร็จ" → เปิดคลัง เลือกโปรแกรม แล้วโหลดไฟล์ (อีเมลยืนยันจะพิมพ์ใน terminal)

คำสั่งอื่น:

```bash
npm test                 # เทสต์อัตโนมัติ (สั่งซื้อ → webhook → ดาวน์โหลด → หมดอายุ/เกินจำนวน → webhook ซ้ำ)
npm run dev              # รันแบบรีสตาร์ตเองเมื่อแก้โค้ด
npm run render -- ...    # เรนเดอร์แอนิเมชันใหม่ (ดูด้านล่าง)
npm run verify -- slug   # ตรวจไฟล์ที่เรนเดอร์ด้วย ffprobe + เฟรมกลางคลิป
```

ครั้งแรกที่จะเรนเดอร์ ต้องโหลด Chromium ก่อน: `npx playwright install chromium` (หรือถ้ามี Google Chrome ในเครื่องอยู่แล้ว สคริปต์จะใช้ Chrome แทนเอง)
ถ้า ffmpeg/ffprobe ไม่อยู่ใน PATH ให้ตั้ง `FFMPEG_PATH` และ `FFPROBE_PATH`

## โครงสร้างโปรเจกต์

```
config/
  products.json        รายการสินค้า (ชื่อ ราคา คำอธิบาย คำถามที่พบบ่อย)
  editors.json         ตารางจับคู่ โปรแกรมตัดต่อ → ไฟล์ที่ได้ + คู่มือแต่ละโปรแกรม
render/
  render.js            สคริปต์เรนเดอร์ (ใส่ข้อความใหม่ → ได้ไฟล์ครบทุกฟอร์แมต)
  template.html        หน้าตา/ท่าเคลื่อนไหวของข้อความ
  verify.js            ตรวจไฟล์ด้วย ffprobe + วิเคราะห์เฟรมกลางคลิป
storage/products/<slug>/   ไฟล์ที่ขาย (อยู่นอก public เข้าถึงได้ผ่านลิงก์ที่เซ็นแล้วเท่านั้น)
public/                    ไฟล์หน้าเว็บ + คลิปพรีวิวมีลายน้ำ
src/
  server.js            จุดเริ่มรัน
  app.js               เส้นทางเว็บทั้งหมด (ร้าน, บัญชี, สั่งซื้อ, webhook, คลัง, หลังบ้าน)
  auth.js              รหัสผ่าน (scrypt), เซสชัน, คุกกี้
  payments/            adapter การชำระเงิน (mock = โหมดทดสอบ, gateway-template.js = โครงสำหรับของจริง)
  links.js             ลิงก์ดาวน์โหลดเซ็นด้วย HMAC
  mailer.js            อีเมล (console / smtp)
  views.js             หน้าเว็บภาษาไทย
  db.js                ตาราง SQLite
fonts/                 ฟอนต์ Kanit + OFL.txt (สัญญาอนุญาต)
test/                  เทสต์อัตโนมัติ
docs/ทดสอบในโปรแกรมจริง.md   checklist ทดสอบในโปรแกรมตัดต่อจริง
```

## ไฟล์ที่ได้ต่อ 1 สินค้า (4 ฟอร์แมต x 2 ขนาด)

| ฟอร์แมต | รายละเอียด | ใช้กับ |
|---|---|---|
| MP4 พื้นเขียว | H.264, yuv420p, พื้น #00FF00 | Chroma Key (CapCut ฯลฯ) |
| MP4 พื้นดำ | H.264, yuv420p | โหมดผสม Screen/Add |
| MOV ProRes 4444 | prores_ks profile 4444, yuva444p10le, โปร่งใสจริง | Premiere, DaVinci, Final Cut |
| WebM VP9 | yuva420p, โปร่งใส | เว็บ, OBS |

ขนาด: แนวตั้ง 1080x1920 และแนวนอน 1920x1080 · 3 วินาที · 30fps (90 เฟรม)
ทุกชุดแนบ `Kanit-OFL.txt` (สัญญาฟอนต์) ไปด้วย

### ชุด 3 ส่วน (ยืดความยาวได้)

ทุกสินค้ามีชุด 3 ส่วนให้ลูกค้าวางเรียงกันแล้วลากภาพนิ่งให้ยาวเท่าที่ต้องการ:

| ส่วน | ไฟล์ | ความยาว |
|---|---|---|
| 1. ส่วนเข้า | `<slug>_parts_green_intro_WxH.mp4` (พื้นเขียว) และ `<slug>_parts_prores_intro_WxH.mov` (โปร่งใส) | 0.8 วินาที (24 เฟรม) |
| 2. ภาพนิ่ง | `<slug>_still_WxH.png` PNG โปร่งใส (เฟรมที่ 30) | ลากยาวได้ไม่จำกัด |
| 3. ส่วนออก | `<slug>_parts_green_outro_WxH.mp4` และ `<slug>_parts_prores_outro_WxH.mov` | 0.5 วินาที (15 เฟรม) |

เฟรมสุดท้ายของส่วนเข้า = ภาพนิ่ง = เฟรมแรกของส่วนออก `npm run verify` ตรวจรอยต่อนี้ให้ด้วย
ไฟล์ไหนไปกับโปรแกรมไหน และคู่มือยืดภาพนิ่ง (`kitGuide`) อยู่ใน `config/editors.json`:
CapCut ได้ชุดพื้นเขียว + PNG, Premiere/DaVinci/Final Cut ได้ชุด ProRes + PNG, "อื่นๆ" ได้ทั้งหมด

## เพิ่มสินค้าใหม่

1. **เรนเดอร์ไฟล์**
   ```bash
   npm run render -- --text "กดติดตาม" --slug follow
   # เลือกสีได้: --fill "#FFFFFF" --stroke "#E11D48"
   ```
   ได้ไฟล์ 8 ไฟล์ใน `storage/products/follow/` และพรีวิวมีลายน้ำใน `public/previews/`
   (`--slug` ใช้ a-z, 0-9, ขีด เท่านั้น เพราะเป็นชื่อไฟล์และ URL)

2. **ตรวจไฟล์**
   ```bash
   npm run verify -- follow
   ```
   ต้องขึ้น "ผ่านทั้งหมด 8 ไฟล์" แล้วเปิดภาพใน `storage/verify/follow/` ดูด้วยตาว่าสระ/วรรณยุกต์ครบ

3. **เพิ่มในร้าน** แก้ `config/products.json` เพิ่มรายการ:
   ```json
   {
     "slug": "follow",
     "title": "กดติดตาม",
     "subtitle": "ข้อความเด้งเข้า สีขาวขอบแดง",
     "price": 4900,
     "description": "...",
     "faq": [{ "q": "คำถาม", "a": "คำตอบ" }]
   }
   ```
   `price` เป็น **สตางค์** (4900 = 49 บาท)

4. รีสตาร์ต `npm start`

**เปลี่ยนท่าเคลื่อนไหว/หน้าตา:** แก้ `render/template.html` (ฟังก์ชัน `setTime` คือท่า, CSS คือสี/ฟอนต์) และเวลาใน `render/render.js` (`TIMING`)
ฟอนต์ใหม่ต้องมีสิทธิ์ใช้เชิงพาณิชย์ และใส่ไฟล์สัญญาไว้ด้วย

**แก้ว่าโปรแกรมไหนได้ไฟล์อะไร / คู่มือ:** แก้ `config/editors.json`

## การชำระเงิน: ทำงานอย่างไร

```
ลูกค้ากดสั่งซื้อ → สร้างคำสั่งซื้อ (pending, ราคาจาก config ฝั่งเซิร์ฟเวอร์)
               → adapter.createCheckout() → พาลูกค้าไปหน้าจ่ายเงิน
Gateway ยิง webhook → POST /webhooks/payment
               → ตรวจลายเซ็น (ผิด = 400) → บันทึก event_id (ซ้ำ = ข้าม)
               → ยอดเงินตรงไหม → เปลี่ยนเป็น paid → สินค้าโผล่ในคลังของบัญชี → ส่งอีเมลยืนยัน (ไม่มีลิงก์ดาวน์โหลด)
หน้าลูกค้า     → ถามสถานะจากเซิร์ฟเวอร์เท่านั้น (ไม่มีทางที่หน้าลูกค้าจะเปลี่ยนสถานะเอง)
```

ในโหมดทดสอบ ปุ่ม "จำลองจ่ายสำเร็จ" ให้ **เซิร์ฟเวอร์** สร้าง webhook ที่เซ็นด้วย `PAYMENT_WEBHOOK_SECRET` แล้วยิงเข้า `/webhooks/payment` เหมือน gateway จริง จึงทดสอบเส้นทางเดียวกับของจริง

ร้าน **ไม่รับและไม่เก็บข้อมูลบัตร** ลูกค้ากรอกบัตร/สแกน QR บนหน้าของ gateway เท่านั้น

## เปลี่ยนเป็นจ่ายเงินจริง

ยังไม่ได้เลือก gateway (ต้องตัดสินใจเอง เพราะเกี่ยวกับสัญญา ค่าธรรมเนียม และบัญชีธุรกิจ)
gateway ที่เลือกควรมี: QR PromptPay + บัตร, หน้าชำระเงินของ gateway เอง (hosted checkout), webhook ที่มีลายเซ็น, โหมด test

ขั้นตอนเมื่อเลือกแล้ว:

1. สมัครและยืนยันตัวตนร้านกับ gateway เปิดโหมด test ของ gateway ก่อน
2. คัดลอก `src/payments/gateway-template.js` เป็น `src/payments/<ชื่อ>.js` แล้วเติม
   - `createCheckout()` เรียก API สร้างการชำระเงิน (amount เป็นสตางค์, ใส่ `order.id` ใน metadata, return URL = `${BASE_URL}/order/<id>`)
   - `parseWebhook()` ตรวจลายเซ็นตามเอกสาร gateway แล้วคืน `{ eventId, type: 'payment.succeeded', orderId, amount, currency, paymentRef }`
3. เพิ่ม `case` ใน `src/payments/index.js`
4. `.env`: `PAYMENT_PROVIDER=<ชื่อ>`, `PAYMENT_API_KEY=...`, `PAYMENT_WEBHOOK_SECRET=<secret จาก dashboard>`
5. ตั้ง URL webhook ใน dashboard ของ gateway เป็น `https://<โดเมน>/webhooks/payment`
6. เพิ่มเทสต์ของ adapter (ลายเซ็นถูก/ผิด, payload จริงจากเอกสาร) แล้วลองจ่ายจริงจำนวนน้อยด้วยโหมด test ของ gateway

## ส่งอีเมลจริง

`.env`: `MAIL_MODE=smtp`, `MAIL_FROM`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`
(ใช้บริการส่งอีเมลที่มี SMTP เช่นบริการอีเมลธุรกิจ ตั้ง SPF/DKIM ของโดเมนด้วย ไม่งั้นอีเมลจะเข้าสแปม)

## ความปลอดภัยที่ทำไว้แล้ว

- บัญชีลูกค้า: รหัสผ่านเก็บเป็น scrypt (salt สุ่มต่อคน), คุกกี้เซสชัน HttpOnly + SameSite=Lax (+ Secure เมื่อเป็น https), ฐานข้อมูลเก็บแค่ SHA-256 ของ token
- ทุกฟอร์มที่ POST มี CSRF token (double-submit cookie แบบ SameSite=Strict)
- ล็อกอินผิด 5 ครั้งต่ออีเมล หรือ 20 ครั้งต่อ IP ใน 15 นาที → ล็อกชั่วคราว, ข้อความผิดพลาดเหมือนกันไม่ว่าอีเมลมีหรือไม่มี, `next` รับเฉพาะ path ในเว็บ
- ไฟล์ที่ขายอยู่ใน `storage/` นอก `public/` โหลดได้จากคลังเท่านั้น: กดในคลัง → ตรวจว่าเป็นเจ้าของ + จ่ายแล้ว → ออกลิงก์ `/d/...` เซ็นด้วย HMAC-SHA256 อายุ 10 นาที (`DOWNLOAD_LINK_MINUTES`)
- ลิงก์ที่เซ็นแล้วไม่ต้องใช้คุกกี้ (ใช้กับโปรแกรมช่วยโหลดได้) แต่แก้วันหมดอายุหรือรหัสในลิงก์ไม่ได้
- กันแชร์บัญชี/โหลดผิดปกติ: บัญชีหนึ่งกดโหลดได้ 60 ไฟล์ต่อ 24 ชั่วโมง (`DOWNLOAD_DAILY_LIMIT`) ไม่จำกัดต่อไฟล์ เพราะเจ้าของโหลดซ้ำได้ตลอด
- คำสั่งซื้อ/คลังของคนอื่น ตอบ 404 เหมือนไม่มี
- โหลดได้เฉพาะไฟล์ของสินค้าที่ซื้อ และเป็นฟอร์แมตของโปรแกรมที่เลือก (ชื่อไฟล์ต้องตรงกับ manifest กัน path traversal)
- webhook: ตรวจลายเซ็นแบบ timing-safe, ปฏิเสธลายเซ็นเก่าเกิน 5 นาที, กันซ้ำด้วย event_id, ตรวจยอดเงินตรงกับคำสั่งซื้อ, webhook ซ้ำไม่ทำซ้ำ (สถานะเปลี่ยนจากรอจ่ายเป็นจ่ายแล้วได้ครั้งเดียว)
- secret ทั้งหมดอยู่ใน `.env` (ไม่อยู่ในโค้ด) มี `.env.example` ให้ดู
- หลังบ้านใช้รหัสผ่านจาก env (Basic auth, ผู้ใช้ admin)
- `NODE_ENV=production` จะไม่ยอมรันถ้ายังเป็น mock, ไม่ใช่ https หรืออีเมลยังเป็น console
- ส่วนหัว CSP, no-referrer (ลิงก์ที่มีลายเซ็นไม่รั่วผ่าน Referer), noindex หน้าดาวน์โหลด

## หลังบ้าน

`/admin` — คำสั่งซื้อ 200 รายการล่าสุด (บัญชีที่ซื้อ, จำนวนไฟล์ที่โหลดจากคลัง), จำนวนสมาชิก, ยอดขาย,
สถิติว่าลูกค้าโหลดไฟล์ไปใช้กับโปรแกรมไหน (นับจากประวัติการโหลดในคลัง)
ลูกค้าโหลดใหม่ได้เองจากคลัง หลังบ้านจึงไม่ต้องส่งลิงก์ให้

## ปรับแต่งแอนิเมชันหลังซื้อ (เวอร์ชันของฉัน)

ในคลัง กด **ปรับแต่ง** ที่สินค้าที่ซื้อแล้ว:

1. พิมพ์ประโยคเอง (ไม่เกิน 40 ตัวอักษร นับสระ/วรรณยุกต์รวมกับพยัญชนะ) เลือกฟอนต์ สีตัวอักษร ขอบ (ไม่มี/บาง/กลาง/หนา + สี) และเงา
2. ดูตัวอย่างเคลื่อนไหวสดในเบราว์เซอร์ (16:9 / 9:16, เปลี่ยนพื้นหลัง, หยุด/เลื่อนดูทีละเฟรม) ใช้ท่าจาก `public/motion.js` ไฟล์เดียวกับที่ใช้เรนเดอร์จริง
3. กด **สร้างไฟล์ของฉัน** → เข้าคิวเรนเดอร์เบื้องหลัง มีแถบความคืบหน้า ปิดหน้าได้
4. เสร็จแล้วอยู่ใน "เวอร์ชันของฉัน" ในคลังตลอด: ชุด 3 ส่วน + คลิปเต็มตามโปรแกรมที่เลือก + ไฟล์สัญญาฟอนต์ โหลดผ่านลิงก์ที่เซ็นแล้ว (`/c/...`) อายุ 10 นาที

- เรนเดอร์ด้วย pipeline เดียวกับสินค้า (`renderCustom()` ใน `render/render.js`): Chrome วาดเฟรมด้วย HTML/CSS แล้ว ffmpeg เข้ารหัส ไม่ใช้ drawtext สระ/วรรณยุกต์ไทยจึงถูกต้อง
- ข้อความใส่ในหน้าเรนเดอร์ด้วย `textContent` (ไม่ใช่ HTML) และกรองที่เซิร์ฟเวอร์: ตัดอักขระควบคุม/อักขระซ่อน, รับเฉพาะไทย/อังกฤษ/ตัวเลข/เครื่องหมายทั่วไป, ไม่รับ `< > \` \\` และอีโมจิ
- ฟอนต์ 12 แบบ ทุกตัวเป็น SIL Open Font License (ใช้เชิงพาณิชย์ได้) อยู่ที่ `public/fonts/thai/<id>/` คู่กับ `OFL.txt` · รายการและน้ำหนักที่ใช้อยู่ใน `config/fonts.json`
  (Kanit, Prompt, Mitr, Sarabun, Noto Sans Thai, Chakra Petch, Bai Jamjuree, Athiti, Pridi, Mali, Itim, Sriracha)
- **สร้างได้ไม่จำกัดครั้ง** กันเครื่องล่มด้วย: เรนเดอร์ทีละงานทั้งร้าน (`CUSTOM_CONCURRENCY`), บัญชีหนึ่งมีงานค้างได้ 1 งาน (`CUSTOM_MAX_ACTIVE`),
  และโควตาพื้นที่เก็บเวอร์ชันต่อบัญชี 3 GB (`CUSTOM_STORAGE_MB`) เต็มแล้วลบเวอร์ชันเก่าก็สร้างต่อได้ · `CUSTOM_DAILY_LIMIT` ตั้งได้ถ้าอยากจำกัดต่อวัน (ค่าเริ่มต้น 0 = ไม่จำกัด)

### ดาวน์โหลดไฟล์เดียว (ไฟล์วิดีโอ ไม่ใช่ zip)
- ลูกค้าเลือกแนว (ตั้ง 9:16 / นอน 16:9) และความยาว (3, 5, 10, 15, 30 วินาที) เรนเดอร์เฉพาะแนวที่เลือก ได้ไฟล์วิดีโอไฟล์เดียว
  (แทนชุด 3 ส่วนเดิม: เลือกความยาวตอนสร้างได้เลย ไม่ต้องยืดในโปรแกรม)
- ชนิดไฟล์ตามโปรแกรม (`single` / `alt` ใน config/editors.json): CapCut = MP4 พื้นเขียว (ทางเลือก: พื้นดำ),
  Premiere/DaVinci/Final Cut = MOV ProRes 4444 โปร่งใส (ทางเลือก: MP4 พื้นเขียว ไฟล์เล็กกว่ามาก)
- เร็ว: วาดเฉพาะเฟรมที่ไม่ซ้ำ 31 เฟรม (`renderSingle()` ใน render/render.js) ต่อเฟรมค้างด้วย hard link เข้ารหัสครั้งเดียว ใช้เบราว์เซอร์ค้างไว้ระหว่างงาน
  วัดจริงบน Mac: CapCut แนวตั้ง 5 วิ ~5 วินาที ไฟล์ 144 KB · Premiere แนวนอน 5 วิ ~3 วินาที ไฟล์ 24.6 MB (ProRes ไฟล์โตตามความยาว ~5 MB/วินาที)
- วิธีใช้และหมายเหตุฟอนต์แสดงบนหน้าผลลัพธ์ ไม่ใส่ในไฟล์ · ส่งไฟล์ตรงจากดิสก์ (มี Content-Length) ผ่านลิงก์ที่เซ็นแล้ว 10 นาที เฉพาะเจ้าของ
- แบบต้นฉบับในคลัง: เลือกโปรแกรม + แนว แล้วโหลดคลิป 3 วินาทีไฟล์เดียว

### ทางลัดที่ทำให้ใช้ง่าย
- ในหน้าปรับแต่ง กด "+ ใช้ฟอนต์ของฉันเอง" เลือกไฟล์ → ฟอนต์ถูกเลือกให้และเห็นในตัวอย่างทันที (ไม่ต้องออกจากหน้า) เตือนทันทีถ้าไม่มีอักษรไทย
- อัปโหลดจากหน้า "ฟอนต์ของฉัน" แล้วระบบพาไปหน้าปรับแต่งพร้อมเลือกฟอนต์นั้นให้ (`?font=u-<id>` ใช้ได้เฉพาะฟอนต์ของตัวเอง)
- หน้าผลลัพธ์มี "ทำอีกแบบจากเวอร์ชันนี้" (`?from=<id>`) เริ่มจากค่าเดิม ไม่ต้องตั้งใหม่
- เลือกโปรแกรมเป็นปุ่มกดในหน้าปรับแต่ง (จำค่าล่าสุดไว้) · ในคลัง ปุ่มหลักคือ "ปรับแต่งแล้วโหลด" · รายการ "เวอร์ชันของฉัน" มีปุ่มดาวน์โหลดในแถวเลย

### สไตล์ของฉัน (ใช้ซ้ำแบบกดทีเดียว)
- "สไตล์" = หน้าตาอย่างเดียว: ฟอนต์ สีตัวอักษร ขอบ (ความหนา+สี) เงา · ไม่รวมข้อความ กดใช้แล้วประโยคที่พิมพ์ไว้ไม่เปลี่ยน
- แถบ "สไตล์ของฉัน" อยู่บนสุดของหน้าปรับแต่ง: กดชื่อสไตล์ → ตัวอย่างเปลี่ยนทันที (ไม่โหลดหน้าใหม่) · "+ บันทึกสไตล์นี้" ถามแค่ชื่อ (เว้นว่างได้) · × เพื่อลบ
- มีปุ่ม "ล่าสุด" อัตโนมัติ = ค่าที่ใช้สร้างไฟล์ครั้งล่าสุด
- `/library/styles` เปลี่ยนชื่อ ลบ และ "ใช้กับ…" แอนิเมชันไหนก็ได้ (`?style=<id>`) · สูงสุด 200 แบบต่อบัญชี
- API ที่หน้าใช้: `POST /library/styles` (JSON + header `x-csrf-token`), `POST /library/styles/<id>/delete`, `POST /library/styles/<id>/rename` · เฉพาะเจ้าของ

### ฟอนต์ของลูกค้า (อัปโหลดเอง)
- `/library/fonts` อัปโหลด .ttf .otf .woff .woff2 (ไม่เกิน 5 MB, 20 ไฟล์ต่อบัญชี `USER_FONT_MAX`) ต้องติ๊กยืนยันว่ามีสิทธิ์ใช้เชิงพาณิชย์
- ตรวจไฟล์จริงใน `src/fontcheck.js`: หัวไฟล์ ตารางที่จำเป็น ขอบเขตทุกตาราง คลายบีบอัด WOFF/WOFF2 แบบจำกัดขนาด แล้วอ่าน cmap ว่ามีตัวอักษรไหนบ้าง (เตือนถ้าไม่มีอักษรไทย) และอ่านชื่อฟอนต์
- ถ้าฟอนต์ไม่มีตัวอักษรที่พิมพ์ หน้าปรับแต่งเตือนทันที และเซิร์ฟเวอร์ไม่ยอมสร้างไฟล์ (กันเบราว์เซอร์แอบใช้ฟอนต์อื่นแทน)
- ไฟล์เก็บที่ `storage/user-fonts/<บัญชี>/` (นอก public, ไม่อยู่ใน git) ส่งให้เจ้าของเท่านั้นผ่าน `/library/fonts/<id>/file` คนอื่นได้ 404 และใช้ในงานของคนอื่นไม่ได้
- งานที่ใช้ฟอนต์ของลูกค้า แนบ `FONT-NOTE.txt` บอกชื่อฟอนต์ และระบุว่าร้านไม่ได้ให้สิทธิ์ใช้งานฟอนต์นั้น (ไม่แนบสัญญาใดๆ แทน)
- ไฟล์อยู่ที่ `storage/custom/<id>/` (ไม่อยู่ใน git) ลูกค้าลบเวอร์ชันของตัวเองได้ · งานที่ค้างตอนปิดร้านจะกลับเข้าคิวเมื่อเปิดใหม่
- เครื่องที่จะเรนเดอร์ต้องมี ffmpeg (มี libx264, prores_ks, libvpx-vp9) และ Chrome/Chromium ร้านจะบอกสถานะตอนเริ่ม (`npm start`) และในหน้า `/admin`
  ร้านติดตั้ง ffmpeg/ffprobe มากับโปรเจกต์แล้ว (`ffmpeg-static`, `ffprobe-static` ใน devDependencies) `npm install` ครั้งเดียวก็ใช้ได้
  (จะใช้ ffmpeg ของเครื่องแทนก็ได้ โดยตั้ง `FFMPEG_PATH` / `FFPROBE_PATH`) · ทดสอบจริงบน Mac: CapCut ~22 วินาที, Premiere (ProRes) ~28 วินาทีต่องาน

## บัญชี คลัง และ "ซื้อแล้วใช้ได้ตลอด"

- ต้องเข้าสู่ระบบก่อนซื้อ คำสั่งซื้อผูกกับบัญชี และใช้อีเมลของบัญชีส่งใบยืนยัน
- `/library` คลังของฉัน: ทุกอย่างที่ซื้อแล้ว กด "ใช้งาน" → เลือกโปรแกรม (จำไว้ให้ครั้งหน้า) → เห็นคลิปเต็ม + ชุด 3 ส่วน + วิธีใช้
- สินค้าที่มีในคลังแล้ว ซื้อซ้ำไม่ได้ ปุ่มจะเปลี่ยนเป็น "เปิดใช้จากคลัง"
- สิทธิ์การใช้งานแบบถาวร ข้อความอยู่ที่ `LICENSE` ใน `src/views.js` แสดงที่หน้าสินค้า คลัง อีเมล และ `/license`
- ฐานข้อมูลรุ่นก่อน (คำสั่งซื้อที่ไม่มีบัญชี / 1 คำสั่งซื้อ = 1 ลิงก์) ย้ายให้อัตโนมัติตอนเปิดร้าน ข้อมูลเดิมไม่หาย
  คำสั่งซื้อเก่าที่ไม่มีบัญชีจะไม่โผล่ในคลังของใคร (ยังไม่มีการยืนยันอีเมล จึงไม่ผูกให้อัตโนมัติ)

## ก่อนขายจริงต้องทำอะไร

- [ ] เลือก payment gateway แล้วเขียน adapter ตามหัวข้อด้านบน
- [ ] ตั้งอีเมลจริง (SMTP) และ SPF/DKIM ของโดเมน
- [ ] เช่าเซิร์ฟเวอร์ + โดเมน + https, ตั้ง `NODE_ENV=production`, `BASE_URL=https://...`
- [ ] สุ่ม secret ใหม่ทั้งหมดบนเซิร์ฟเวอร์จริง (อย่าใช้ `.env` จากเครื่องทดสอบ)
- [ ] สำรองไฟล์ `data/shop.db` เป็นประจำ
- [ ] ยืนยันอีเมลตอนสมัคร และหน้า "ลืมรหัสผ่าน" (ต้องมีอีเมลจริงก่อน)
- [ ] ใส่ rate limit หน้า `/signup`, `/checkout` และ `/admin` (หรือใช้ของ reverse proxy/Cloudflare) กันสแปม/เดารหัส
- [ ] หน้านโยบาย: เงื่อนไขการใช้งาน/สิทธิ์การใช้ไฟล์, นโยบายคืนเงิน, นโยบายความเป็นส่วนตัว (PDPA เพราะเก็บอีเมล), ช่องทางติดต่อร้าน
- [ ] ทดสอบไฟล์ในโปรแกรมจริงตาม `docs/ทดสอบในโปรแกรมจริง.md`
- [ ] ถ้ามีสินค้าหลายชิ้นหรือไฟล์ใหญ่ขึ้น พิจารณาเก็บไฟล์บน object storage (เช่น S3/R2) แล้วออก signed URL แทนการส่งจากเซิร์ฟเวอร์เอง
